GMAO — Matériel hydrométrique

Documentation d'utilisation, d'architecture et de suivi des évolutions

Utilisation

Lancer l'application locale

L'appli sert à consulter/modifier la base (dashboard, formulaires). Elle utilise un environnement Python dédié (venv) où Flask est installé — ne pas la lancer avec le Python système (ça produit une erreur ModuleNotFoundError: No module named 'flask', typique si on utilise le bouton "Run" d'un IDE comme Thonny au lieu du venv du projet).

"GMAO\venv\Scripts\python.exe" "GMAO\run.py"

Puis ouvrir http://localhost:5000 dans un navigateur. Cette page d'aide est aussi accessible directement depuis l'appli via le lien 📖 Aide en haut de chaque page.

Vue globale (dashboard)

Page d'accueil : liste de tous les équipements avec leur site actuel. Le menu déroulant filtre par site, le champ de recherche filtre par nom d'équipement (les deux se combinent).

Ajouter un équipement

Bouton + Nouvel équipement en haut de page : nom, site d'affectation (menu déroulant listant les sites déjà utilisés, avec une option + Nouveau site... pour en créer un directement depuis le formulaire), date d'installation. Un identifiant technique unique est généré automatiquement (utilisé plus tard dans l'URL du QR code).

La date saisie dans ce formulaire est la date d'installation du matériel (qui peut être dans le passé). La date d'affectation au site choisi est toujours celle du jour de la création dans l'outil — les deux dates sont indépendantes.

Changer l'affectation d'un équipement

Depuis la fiche détail d'un équipement → Changer l'affectation : indiquer le nouveau site et la date de transfert. L'ancienne affectation est automatiquement clôturée (date de fin renseignée) et une nouvelle ligne d'historique est créée. L'historique n'est jamais réécrit, seulement complété.

Générer les QR codes d'une sélection

Depuis le dashboard, cochez les équipements voulus, ou utilisez les boutons Tout sélectionner / Tout désélectionner (comme la case en tête de tableau, ils ne touchent que ce qui est actuellement affiché — donc respectent les filtres site/recherche en cours). Cliquez ensuite sur Générer les QR codes de la sélection : la planche imprimable ne contiendra que ces équipements et s'ouvre directement dans un nouvel onglet, prête à imprimer.

Publier les fiches et générer les QR codes (tous les équipements)

Après une ou plusieurs modifications, deux scripts régénèrent le contenu à publier :

"GMAO\venv\Scripts\python.exe" "GMAO\scripts\generate_site.py"
"GMAO\venv\Scripts\python.exe" "GMAO\scripts\generate_qrcodes.py"

Le premier régénère les fiches HTML (une par équipement) dans docs/e/. Le second régénère les QR codes individuels et la planche imprimable dans etiquettes/ (fichier planche_etiquettes.html — à ouvrir dans un navigateur et imprimer). Il faut ensuite pousser les changements vers GitHub pour que les fiches en ligne soient à jour (git add -A, git commit, git push).

Étiquettes

Chaque étiquette imprimée porte le QR code et le nom de l'équipement en clair — utile si le réseau mobile est absent ou instable sur le site (cas fréquent pour du matériel isolé), pour au moins identifier visuellement le matériel sans avoir à scanner.

Architecture

Le principe central : le QR code n'encode jamais les données du matériel directement (elles deviendraient fausses au premier changement d'affectation), mais un lien stable vers une fiche consultée en ligne, générée dynamiquement depuis la base.

1. Base SQLite (data/gmao.db) — source de vérité unique : table equipement (nom, date d'installation) et table affectation (site, date de début, date de fin — NULL = affectation en cours). L'historique se déduit naturellement de cette seconde table.
↓ édité via
2. Appli Flask locale (run.py + app/) — dashboard, formulaires de création/changement d'affectation. Usage local uniquement, pas exposée sur Internet.
↓ génère
3. Générateurs statiques (scripts/generate_site.py, scripts/generate_qrcodes.py) — produisent une fiche HTML autonome par équipement (docs/e/<id>.html) et les QR codes correspondants (etiquettes/).
↓ publié via git push
4. GitHub Pages (github.com/SPCMO/GMAO, dossier docs/) — hébergement public gratuit des fiches, accessible depuis un smartphone en scannant le QR code, y compris hors réseau interne.

Usage multi-postes

Chaque poste garde sa propre copie du code (son propre .bat), mais peut pointer vers une base SQLite partagée sur le réseau au lieu de sa base locale, via le menu ⚙️ Paramètres. Tous les postes configurés sur le même chemin réseau voient alors les mêmes équipements et affectations. Le chemin choisi est propre à chaque poste (fichier settings.json, non versionné) — chacun le configure une fois.

SQLite sur un partage réseau tolère bien un usage occasionnel à quelques personnes, mais n'est pas conçu pour des écritures strictement simultanées par de nombreux utilisateurs. Si l'usage se développe fortement, un vrai serveur central (une seule instance de l'appli, accédée par navigateur) serait plus robuste.

Paramétrage

Le fichier config.py, à la racine du projet, centralise les réglages :

ParamètreRôle
DB_PATHEmplacement par défaut de la base SQLite (utilisé si aucun réglage n'est enregistré dans settings.json)
DOCS_DIRDossier des fiches statiques générées (publié via GitHub Pages)
ETIQUETTES_DIRDossier des QR codes et de la planche imprimable
FICHE_BASE_URLURL publique de base des fiches — à modifier uniquement si le dépôt ou son adresse GitHub Pages change, puis relancer generate_qrcodes.py pour régénérer des QR codes à jour

Installer l'appli sur un nouveau poste

Le dossier réseau (2026_GMAO) sert de copie du code et de stockage de la base partagée — il ne contient volontairement pas d'environnement Python (venv), et Lancer_GMAO.bat ne peut pas s'exécuter directement dessus (Windows ne supporte pas un dossier réseau \\... comme répertoire de travail). Pour un nouveau poste :

  1. Copier tout le dossier GMAO (depuis le réseau ou GitHub) sur le disque local, par exemple D:\GMAO
  2. Ouvrir une invite de commande dans ce dossier et créer l'environnement : 
    python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
  3. Lancer Lancer_GMAO.bat, puis dans le menu ⚙️ Paramètres, indiquer le chemin réseau de la base partagée (voir ci-dessous)

Emplacement de la base (menu Paramètres)

Le menu ⚙️ Paramètres de l'appli permet de changer l'emplacement de la base SQLite sans toucher au code : local (par défaut) ou chemin réseau partagé, par exemple :

\\10.11.208.239\suivi\Suivi_hydrométrie\00_Projets_en_cours\2026_GMAO\data\gmao.db

Ce choix est enregistré dans settings.json à la racine du projet — un fichier propre à chaque poste, exclu du dépôt git (.gitignore), donc jamais publié sur GitHub. C'est ce qui permet de garder un chemin réseau interne hors du dépôt public.

Trois destinations de déploiement

Comme pour les autres outils du service, chaque modification du code est déployée vers trois emplacements :

  1. Dossier local — là où le code est modifié
  2. Réseau SPCMO — \\10.11.208.239\suivi\Suivi_hydrométrie\00_Projets_en_cours\2026_GMAO, copie complète de l'outil (héberge aussi la base partagée pour l'usage multi-postes)
  3. GitHub public — github.com/SPCMO/GMAO, pour l'hébergement des fiches (GitHub Pages)
La base de données du dossier réseau (data/gmao.db) n'est jamais écrasée par ces synchronisations de code — seuls les fichiers du programme sont mis à jour, pour ne pas perdre les données saisies par les utilisateurs.

Hébergement GitHub Pages

Dépôt : github.com/SPCMO/GMAO (public). Publication activée sur la branche main, dossier /docs. Le fichier docs/.nojekyll désactive le traitement Jekyll (inutile pour du HTML statique, et source de lenteurs au déploiement sans lui).

Sécurité : le dépôt étant public, son contenu reste techniquement consultable dans son intégralité (pas seulement les fiches individuelles) par quiconque connaît son adresse. Les identifiants d'équipement utilisés dans les URL sont volontairement opaques (non déductibles du nom) pour limiter la découverte, mais ce n'est pas une confidentialité stricte — à reconsidérer si les données venaient à être plus sensibles.

Authentification git

Un token d'accès personnel GitHub (scope Contents uniquement) est enregistré dans la configuration git locale du dépôt pour permettre les git push sans ressaisie. En cas d'expiration ou de révocation, en régénérer un depuis GitHub (Settings → Developer settings → Personal access tokens) et mettre à jour l'URL du remote :

git remote set-url origin "https://<NOUVEAU_TOKEN>@github.com/SPCMO/GMAO.git"
