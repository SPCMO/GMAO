Mise en route de l'automatisation : tâche planifiée quotidienne et envoi des mails d'alerte

🗓️ Planificateur de tâches Windows

Objectif : faire tourner automatiquement, tous les jours à 7h, le script scripts/verifier_alertes.py qui vérifie les péremptions de matériel et envoie un mail par équipement nouvellement en alerte. Ce guide part du principe que le relais mail est déjà configuré et testé (voir l'onglet ✉️ Envoi de mail si ce n'est pas encore fait).

Prérequis : le poste qui exécute la tâche doit rester allumé, connecté au réseau SPCMO (pour lire la base) et à Internet (pour l'envoi) à l'heure prévue. Sur un poste portable, désactiver la mise en veille automatique à cette heure, ou décocher l'option d'alimentation secteur à l'étape 5.

Méthode rapide (une seule commande)

Ouvrir une invite de commandes ou PowerShell classique et coller (en adaptant le chemin si l'appli est installée ailleurs) :

schtasks /create /tn "GMAO - Verification alertes" /sc daily /st 07:00 /tr "\"D:\charles-eddy.piot\Documents\Perso CEP\Git-Claude IA\GMAO\venv\Scripts\python.exe\" \"D:\charles-eddy.piot\Documents\Perso CEP\Git-Claude IA\GMAO\scripts\verifier_alertes.py\""

C'est terminé — passer directement à la section Vérifier que la tâche est bien créée plus bas. La suite de cette page détaille la même opération via l'interface graphique, pour ceux qui préfèrent ne pas taper de commande.

Méthode détaillée (interface graphique)

  1. Ouvrir le Planificateur de tâches

    Clic sur le menu Démarrer, taper Planificateur de tâches (ou Task Scheduler), puis lancer l'application du même nom.

  2. Créer une nouvelle tâche

    Dans le panneau de droite (Actions), cliquer sur Créer une tâche... (pas « Créer une tâche de base », qui offre moins d'options — notamment celle de l'étape 6).

  3. Onglet Général

    NomGMAO - Verification alertes
    Description(optionnel) Vérifie les péremptions de matériel et envoie les mails d'alerte quotidiens

    Cocher Exécuter que l'utilisateur soit connecté ou non si vous voulez que la tâche tourne même sans session ouverte (nécessite de ressaisir le mot de passe Windows du compte à la validation finale).

  4. Onglet Déclencheurs

    Nouveau... → Quotidienne → heure de début 07:00:00, répéter tous les 1 jour(s) → OK.

  5. Onglet Actions

    Nouvelle... → Action : Démarrer un programme, puis remplir :

    Programme/scriptD:\charles-eddy.piot\Documents\Perso CEP\Git-Claude IA\GMAO\venv\Scripts\python.exe
    Ajouter des argumentsscripts\verifier_alertes.py
    Démarrer dansD:\charles-eddy.piot\Documents\Perso CEP\Git-Claude IA\GMAO

    Le champ « Démarrer dans » est important : sans lui, le script ne retrouve pas ses fichiers relatifs (settings.json, etc.).

  6. Onglet Conditions

    Décocher Ne démarrer la tâche que si l'ordinateur est branché sur le secteur si le poste peut être sur batterie à 7h (sinon la tâche est silencieusement ignorée). Laisser Réveiller l'ordinateur pour exécuter cette tâche coché si le poste est parfois en veille à cette heure.

  7. Onglet Paramètres

    Cocher Exécuter la tâche dès que possible après un démarrage manqué — utile si le poste était éteint à 7h précises (arrivée tardive, poste redémarré) : la tâche se déclenchera dès la prochaine ouverture de session.

  8. Valider

    OK, puis ressaisir le mot de passe du compte Windows si demandé (uniquement si l'option de l'étape 3 a été cochée). La tâche apparaît maintenant dans la Bibliothèque du Planificateur de tâches.

Vérifier que la tâche est bien créée

Dans le Planificateur de tâches, sélectionner Bibliothèque du Planificateur de tâches dans le panneau de gauche : la tâche GMAO - Verification alertes doit apparaître dans la liste, avec Prochaine exécution indiquant demain 7h (ou aujourd'hui 7h si créée avant cette heure).

Tester tout de suite (sans attendre 7h)

Clic droit sur la tâche → Exécuter. Puis onglet Historique (en bas, si affiché — sinon l'activer via Activer tout l'historique des tâches dans le panneau Actions à droite) : un événement Terminé (code de sortie 0) confirme un lancement du script sans erreur Python. Le signe le plus fiable que tout fonctionne reste néanmoins de recevoir (ou pas, si aucun matériel n'est en alerte) un mail à l'UH concernée.

Voir ce que le script a réellement fait — par défaut, le Planificateur de tâches n'affiche nulle part les messages que verifier_alertes.py imprime (nombre de mails envoyés, erreurs éventuelles). Pour les conserver dans un fichier consultable, remplacer l'action de l'étape 5 par :
Programme/scriptcmd.exe
Ajouter des arguments/c ""venv\Scripts\python.exe" "scripts\verifier_alertes.py" >> "logs\verifier_alertes.log" 2>&1"

(créer au préalable un dossier logs\ vide dans le projet). Chaque exécution ajoutera une ligne au fichier logs\verifier_alertes.log, consultable avec le Bloc-notes.

Modifier ou supprimer la tâche plus tard

Retour dans le Planificateur de tâches → clic droit sur GMAO - Verification alertes → Propriétés pour modifier, ou Supprimer pour la retirer définitivement.

✉️ Mise en route de l'envoi de mail

Le réseau SPCMO bloque les connexions SMTP sortantes directes (ports 587/465). La solution qui fonctionne : un petit script Google Apps Script, hébergé et exécuté par les serveurs Google (donc jamais bloqué par le réseau SPCMO), qui reçoit une requête HTTPS de GMAO et envoie réellement le mail via Gmail. Ce guide couvre la mise en route complète, à faire une seule fois.

  1. Se connecter au bon compte Google

    Dans un navigateur, se connecter sur script.google.com avec le compte spcmo113466@gmail.com (celui qui enverra effectivement les mails). Si un autre compte Google est déjà connecté sur ce navigateur, utiliser une fenêtre de navigation privée ou changer de compte via l'avatar en haut à droite.

  2. Créer le projet Apps Script

    Cliquer sur Nouveau projet (bouton en haut à gauche). Un éditeur de code s'ouvre avec un fichier Code.gs vide.

  3. Coller le code du relais

    Ouvrir le fichier apps_script/gmao_mail_relay.gs du projet GMAO (avec le Bloc-notes ou un éditeur de texte), tout sélectionner, copier. Dans l'éditeur Apps Script, supprimer le contenu par défaut de Code.gs et coller le code copié.

  4. Choisir un jeton secret

    Dans le code collé, repérer la ligne :

    const TOKEN_SECRET = 'CHANGE_MOI_AVEC_UNE_VALEUR_SECRETE';

    Remplacer CHANGE_MOI_AVEC_UNE_VALEUR_SECRETE par une valeur secrète de votre choix (une phrase ou suite de caractères difficile à deviner, par exemple générée par un gestionnaire de mots de passe). Noter cette valeur quelque part — elle sera resaisie à l'étape 8 dans GMAO. Enregistrer (Ctrl+S ou icône disquette).

  5. Nommer le projet (optionnel mais conseillé)

    Cliquer sur Projet sans titre en haut à gauche, renommer en GMAO - Relais mail, Renommer.

  6. Déployer en tant qu'application web

    Bouton Déployer (en haut à droite) → Nouveau déploiement. Cliquer sur la roue crantée à côté de « Sélectionner le type » → choisir Application Web. Renseigner :

    Description(optionnel) v1
    Exécuter en tant queMoi (spcmo113466@gmail.com)
    Qui a accèsTout le monde

    « Qui a accès : Tout le monde » ne signifie pas que n'importe qui peut envoyer un mail en votre nom : la requête doit fournir le jeton secret de l'étape 4, vérifié dans le code (doPost). C'est l'équivalent d'une clé d'API.

    Cliquer sur Déployer.

  7. Autoriser l'accès (première fois uniquement)

    Google affiche un écran Autoriser l'accès car le script agit sur votre propre compte Gmail. Cliquer sur Autoriser les accès, choisir le compte spcmo113466@gmail.com. Un écran Google n'a pas validé cette application peut apparaître (normal pour un script personnel non publié sur le Play Store) : cliquer sur Paramètres avancés puis Accéder à GMAO - Relais mail (non sécurisé), puis Autoriser sur l'écran suivant listant les permissions (envoi de mail en votre nom). C'est sans risque : le code est celui du dépôt GMAO, que vous venez de coller vous-même.

  8. Récupérer l'URL de déploiement

    Une fenêtre Déploiement réussi affiche une URL de l'application Web qui se termine par /exec. La copier (icône de copie à côté du champ).

  9. Configurer GMAO

    Dans l'application GMAO, menu ⚙️ Paramètres → section 🔗 Relais mail (Google Apps Script) :

    URL du déploiementcoller l'URL de l'étape 8
    Jeton secretla valeur choisie à l'étape 4

    Cliquer sur Enregistrer.

  10. Tester l'envoi

    Toujours dans cette section, champ adresse@test.fr pour un envoi test : saisir une adresse à laquelle vous avez accès, cliquer ✉️ Envoyer un test. Un message Mail de test envoyé à ... confirme le succès ; vérifier la boîte de réception (et les indésirables) de l'adresse testée.

  11. Configurer les destinataires par UH

    Toujours dans ⚙️ Paramètres, section 📬 Destinataires des alertes par UH de gestion : ajouter une ou plusieurs adresses pour chaque UH (11, 34, 66) concernée. Ce sont ces adresses qui recevront les mails d'alerte automatiques — sans destinataire configuré pour une UH, ses alertes ne seront pas envoyées (mais resteront visibles ⚠️ dans le dashboard).

Repli SMTP Un formulaire SMTP classique reste disponible juste au-dessus dans ⚙️ Paramètres, pour le cas où GMAO tournerait un jour sur un réseau qui n'a pas ce blocage. Il n'est pas nécessaire de le remplir si le relais Apps Script fonctionne : GMAO essaie toujours le relais Apps Script en premier, et ne se rabat sur le SMTP direct que si aucune URL de relais n'est configurée.

Et ensuite ?

Une fois le relais testé avec succès, passer à l'onglet 🗓️ Planificateur de tâches pour automatiser la vérification quotidienne à 7h — sans cette tâche planifiée, les alertes ne sont visibles que si quelqu'un ouvre GMAO dans son navigateur.

Limite réseau connue (constatée le 18 août 2026) Sur ce poste (réseau SPCMO/DREAL-OC), le clic ✉️ Envoyer un test dans GMAO se solde parfois par Relais Apps Script injoignable : <urlopen error timed out> — alors que le relais lui-même fonctionne (vérifié indépendamment : réponse en 2 à 4 secondes, mails bien reçus). La cause est la même passerelle de sécurité qui bloque déjà les git push depuis ce poste (voir Aide.html, onglet Paramétrage, section « Authentification git ») : elle semble filtrer les connexions HTTPS sortantes par processus, et laisse passer un navigateur web mais pas un script Python lancé nativement (via l'appli GMAO ou une tâche planifiée). Conséquence concrète : la tâche planifiée quotidienne (onglet précédent) risque de rencontrer le même blocage et de ne jamais réussir à envoyer les mails d'alerte, silencieusement (le script se termine simplement en erreur, sans qu'un humain le remarque tant que personne ne regarde le journal — voir l'astuce de journalisation dans l'onglet précédent).

À faire : tester une fois ✉️ Envoyer un test depuis GMAO ; si l'échec se reproduit, ce n'est pas un problème de configuration côté GMAO ou Apps Script — contacter le support informatique (DREAL-OC / assistance RIE) pour demander une exception de pare-feu sortant sur venv\Scripts\python.exe du dossier GMAO (le même exécutable est aussi concerné par le blocage git push).
